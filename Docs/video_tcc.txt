Na verdade, essa é uma ideia que tenho há bastante tempo, desde antes de começar a faculdade.

Isso já aconteceu várias vezes comigo. Às vezes, os verificadores de preços estão longe, estragados ou nem existem.

Como estamos sempre com o celular na mão, veio a ideia de utilizar ele para consultar os preços.

Então comecei a pesquisar as tecnologias necessárias e, durante a faculdade, vi a oportunidade de transformar essa ideia no meu TCC.

### SLIDE 5 — Tecnologias utilizadas

Para o Android, escolhi Kotlin porque achei mais simples e por ser recomendada pelo Google que já mantem o Android.

Utilizei o Jetpack Compose para criar as telas do aplicativo.

O CameraX facilita o uso da câmera. é oq abre ela.

E o ML Kit foi oq achei mais interessante, porque utiliza inteligência artificial para reconhecer imagens. No projeto, é ele que faz a leitura dos códigos de barras.

O MVVM decidir usar pois é um padrão de arquitetura recomendado para organizar o aplicativo, separando a interface da lógica.

Escolhi o Retrofit porque facilita a comunicação com o backend por HTTP, e o Moshi porque converte o JSON recebido em objetos Kotlin.

No backend, utilizei Python com Django REST Framework e MySQL para armazenar os produtos.

Também utilizei Git e GitHub para controlar as versões. Depois das alterações, executava os testes e, quando estava tudo certo, fazia o commit.

Cada alteração era seguida de teste e se ok, executava Commit.

E também utilizei o ChatGPT como ferramenta de apoio, principalmente para pesquisas, documentação e para me auxiliar a determinar se certa tecnologia era viável e existe e como fazer. tirar dúvidas e auxiliar na identificação e correção de erros e textos.

Estudei sobre IA e como passar instruções e prompts corretos para ela. E sempre conferindo e testando tudo que ela me passava.



### SLIDE 6 — Arquitetura do sistema

**[MOSTRAR O DIAGRAMA "Slide"]**

Aqui podemos ver como o sistema funciona.

Primeiro, o aplicativo localiza o servidor na rede Wi-Fi.

O CameraX fornece as imagens da câmera e o ML Kit identifica o código de barras.

Depois, o Retrofit envia esse código para a API Django.

O Django consulta o banco MySQL e retorna as informações em JSON.

Por fim, o aplicativo mostra o nome, a descrição, o preço e a imagem do produto.

### SLIDE 10 — Tratamento de erros

**[MOSTRAR OS EXEMPLOS NO APLICATIVO]**

Também implementei tratamento de erros.

Quando encontra o produto, a API retorna o código HTTP 200.

Se o código informado for inválido, retorna 400.

E se o produto não estiver cadastrado, retorna 404.

O aplicativo mostra uma mensagem correspondente a cada situação.

### SLIDE 12 — Melhorias futuras

Apesar de o aplicativo já estar funcionando, ainda existem algumas melhorias que eu quero fazer.

Uma das melhorias futuras seria adicionar a leitura de QR Codes, porque, como eu já trabalhei em mercado, soube que existe uma iniciativa para ir substituindo aos poucos os códigos de barras tradicionais por códigos 2D, como o QR Code.

O que mais me interessou foi descobrir que um QR Code pode armazenar mais de 4 mil caracteres.

Isso facilita muito a rastreabilidade dos produtos, porque permite utilizar uma etiqueta com um identificador único para cada unidade, incluindo informações como lote, validade e muitas outras, ajudando a identificar melhor os produtos dentro do mercado.

Outra melhoria nesta mesma linha, seria implementar recursos administrativos para controle de estoque e relatórios.
