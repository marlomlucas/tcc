### SLIDE 1 — Apresentação

Olá, meu nome é Marlom Camaran Lucas, sou acadêmico de Engenharia de Software da UniCesumar.

Meu TCC é o desenvolvimento e a validação de um aplicativo Android para consulta de preços.

A ideia é utilizar a câmera do celular para ler o código de barras e consultar as informações do produto em um servidor.

### SLIDE 2 — Motivação

A ideia surgiu de um problema comum no comércio: preços que faltam ou que estão incorretos e acabam causando confusão.

Também existem estabelecimentos onde os verificadores de preços ficam longe ou são poucos.

A Lei nº 10.962, de 2004, regulamenta a informação dos preços aos consumidores, e o descumprimento das regras pode gerar multas.

Então pensei em criar uma forma de consultar os preços diretamente pelo celular.

### SLIDE 3 — Objetivos

O objetivo principal foi desenvolver e testar um aplicativo Android capaz de consultar produtos pelo código de barras.

Primeiro, pesquisei os requisitos e se seria possível fazer o projeto funcionar.

Depois, estudei sobre APIs, consultas ao banco de dados, funcionamento dos códigos de barras e ferramentas para leitura pela câmera.

Também pesquisei sobre testes de software, para aplicar durante o desenvolvimento.

### SLIDE 5 — Tecnologias utilizadas

Para o Android, escolhi Kotlin porque achei mais simples e por ser recomendada pelo Google.

Utilizei o Jetpack Compose para criar as telas do aplicativo.

O CameraX basicamente facilita o uso da câmera.

E o ML Kit foi uma das ferramentas que mais achei interessantes, porque utiliza recursos de inteligência artificial para reconhecer imagens. No projeto, ele faz a leitura dos códigos de barras.

O MVVM foi utilizado para organizar o código, separando a interface da lógica.

O Retrofit faz a comunicação com o backend por HTTP.

O Moshi converte os dados JSON recebidos da API em objetos Kotlin.

E o Coil carrega as imagens dos produtos.

No backend, utilizei Python com Django e Django REST Framework, e o MySQL para armazenar os produtos.

Também utilizei Git e GitHub para controlar as versões do projeto.

### SLIDE 6 — Arquitetura do sistema

**[MOSTRAR O DIAGRAMA]**

Aqui podemos ver como o sistema funciona.

Primeiro, o aplicativo localiza o servidor na rede Wi-Fi.

O CameraX fornece as imagens da câmera e o ML Kit identifica o código de barras.

Depois, o Retrofit envia esse código para a API Django.

O Django consulta o banco MySQL e retorna as informações em JSON.

Por fim, o aplicativo mostra o nome, a descrição, o preço e a imagem do produto.

### SLIDE 10 — Tratamento de erros

**[MOSTRAR OS EXEMPLOS NO APLICATIVO]**

Também implementei o tratamento de erros para evitar que o aplicativo apresente informações incorretas.

Quando encontra o produto, a API retorna o código HTTP 200.

Se o código informado for inválido, retorna 400.

E se o produto não estiver cadastrado, retorna 404.

O aplicativo mostra uma mensagem correspondente a cada situação.
